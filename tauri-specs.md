# Tauri SDK: specification

Feature-equivalent port of `@licenseman/electron` (v1.1.0, `~/projects/licensemanager-electron`) to Tauri v2. When this spec and the Electron code disagree on a behavior not listed under [intentional differences](#3-intentional-differences), **the Electron code wins**: read the matching file before implementing each module.

## 1. Goals and non-goals

Goals:
- Same features and behavior as the Electron SDK: one license state, validation on every launch, offline tokens, background renewal with backoff, the same error codes, clock tampering detection, machine fingerprint, keychain storage with a file fallback, customer portal link.
- Usable from Rust (the source of truth, where the checks that matter belong) and from the webview (activation screen, locked screens).
- Byte-compatible storage and fingerprint with the Electron SDK, so an app moving from Electron to Tauri keeps its activations.
- Same engineering standard: CI on macOS, Windows and Linux, 80% coverage, Changesets PR flow, automatic publishing with provenance / trusted publishing.

Non-goals for 1.0:
- A standalone Rust crate for apps without Tauri (see "Why one crate" in section 2).
- iOS and Android (no keychain abstraction shared with desktop, no stable machine id). The crate compiles on mobile targets, but the plugin refuses to start there (see 8.6).
- Tauri v1.
- Any change to the API: the SDK only calls `POST /v1/products/{productId}/validate-key`, like the Electron SDK.

## 2. Deliverables

| | Name | Path | Registry |
| --- | --- | --- | --- |
| Rust crate | `tauri-plugin-licensemanager` | repo root (`Cargo.toml`, `src/`) | crates.io |
| JS bindings | `@licenseman/tauri` | repo root (`guest-js/`, built to `dist-js/`) | npm |
| Example app | `tauri-app-example` (not published) | `examples/tauri-app` | |

Repo: `github.com/licenseman/licensemanager-tauri`, MIT. The crate and the npm package share one version and are released together.

**Why one crate.** A Tauri plugin needs at least a crate and a JS package: the webview can't import Rust. A separate Tauri-free core crate (for Rust apps without Tauri) would add a second publish, exact-version pinning between crates and a docs page for a tiny market. Instead, the licensing logic lives in `src/core/`, which must not import `tauri` (checked in CI, see 11.1). Splitting it into its own crate later is then a move plus a re-export from the plugin, with no breaking change.

**Why it isn't generated.** The SDKs in `packages/sdks` (`@licenseman/sdk`, `licenseman-sdk`…) are generated from the OpenAPI spec: one method per endpoint, for backends calling the API with an `lm_` key, released on every spec change. This crate is the Rust version of `@licenseman/electron`, not of `@licenseman/sdk`: a client-side state machine that calls a single endpoint (`validate-key`) without an API key. Like the Electron SDK, it calls that endpoint by hand (`core/api.rs` ports `license-api.ts`), which keeps the dependency tree small (no OpenSSL, no model per endpoint), avoids a release on every unrelated API change, and keeps the error mapping, timeout and retry rules reviewable line by line against Electron. The crate name `licenseman-sdk` stays free for a generated Rust API client, if one is ever added to `packages/sdks`.

## 3. Intentional differences

Everything else must match the Electron SDK.

| Electron | Tauri | Why |
| --- | --- | --- |
| Invalid `publicKey` fails on first verification (as `invalid_response`, or `OFFLINE_EXPIRED` from the stored token). | `LicenseManager::new` parses the PEM and returns `ConfigError::InvalidPublicKey`. | A wrong key is a developer error: fail at startup, not in the field. Empty `productId`/`publicKey` are also `ConfigError`s. |
| `version` defaults to `app.getVersion()`. | Defaults to `app.package_info().version` (from `tauri.conf.json` / `Cargo.toml`). | No Electron to ask. |
| IPC loses the error `code` (docs tell users to return objects). | Command errors are serialized with `code`, `status`, `latestAllowedVersion`; the JS package rethrows a `LicenseError`. | Tauri serializes command errors. |
| The app calls `dispose()`. | The plugin disposes on `RunEvent::Exit`. `app.license().dispose()` stays available. | Plugin lifecycle hook. |
| The app constructs `new LicenseManager(options)`. | The app registers the plugin with a `Builder`; the `LicenseManager` is created in the plugin's setup and reached with `app.license()`. Its constructor is crate-private. | Tauri plugin model; one instance per app for free. |
| Everything callable from the main process. | Webview access goes through permissions; the full key and the fingerprint are not in the default set. | Tauri's capability model; matches the Electron docs' advice "only expose what your windows need". |
| `getLatestAllowedVersion()` returns `string \| null \| undefined`. | Rust: `LatestAllowedVersion` enum; JS: same `string \| null \| undefined`. | No `undefined` in Rust. |
| Listener: `onStateChange(fn)` returns an unsubscribe function. | Rust: `on_state_change(fn)` returns a `Subscription` (unsubscribes on drop) and `subscribe()` returns a `tokio::sync::watch::Receiver`. JS: `onStateChange` returns `Promise<UnlistenFn>`. | Idiomatic in each language. |
| | JS adds `watchLicense(cb)` (subscribe, then fetch the snapshot) and `getLicense()` (state + offline state + latest version in one call). | Avoids the "window opened after a state change" race documented for Electron. |

## 4. Compatibility contract with the Electron SDK

The same product on the same machine must read the same stored values and compute the same fingerprint, whichever SDK runs. Constants and formats, all copied from the Electron code:

| Item | Value |
| --- | --- |
| Keyring service | `dev.licensemanager.sdk` |
| Keyring account | `{productId}:{key}` where key is `installId`, `licenseKey`, `licenseToken` or `lastSeen` |
| Keyring library | `keyring` crate, same major version and backends as the one `@napi-rs/keyring` is built on (check its `Cargo.toml` at implementation time), so entries have the same attributes/target names on each OS. |
| File namespace | `hex(sha256("dev.licensemanager.sdk:" + productId))[0..32]` |
| File name | `hex(sha256(key))[0..24] + ".dat"`, mode `0o600` on Unix |
| File dirs, macOS | `~/Library/Application Support/.{ns}`, `~/Library/Caches/.{ns}` |
| File dirs, Windows | `%PROGRAMDATA%\{ns}` (fallback `~\AppData\{ns}`), `%APPDATA%\{ns}` (fallback `~\AppData\Roaming\{ns}`) |
| File dirs, other | `~/.config/.{ns}`, `~/.local/share/.{ns}` |
| Install id | 32 random bytes, standard base64 with padding |
| Machine component | `base64(sha256(raw machine id))`, standard base64 with padding |
| Fingerprint | `{machine}:{installId}:{productId}` |
| `lastSeen` value | standard base64 of the decimal milliseconds string |

Golden vectors, computed with the Electron implementation, to hard-code in Rust unit tests (`store.rs`, `fingerprint.rs`, `clock.rs`):

| Input | Output |
| --- | --- |
| namespace for productId `x7Kp2QaZ` | `ea8ac6eca49d93514868857bb07922b4` |
| file name for `installId` | `ca8a5f3f684e28ccf496a00b.dat` |
| file name for `licenseKey` | `4d7f38bbfba5e53684683337.dat` |
| file name for `licenseToken` | `110af1ca6fb7b596b2a37cc3.dat` |
| file name for `lastSeen` | `758c78e59ed6d3a1649c33a8.dat` |
| machine hash of `4c4c4544-0042-3510-8051-b4c04f4b4e32` | `WDpaNFX/NZW0yp1UEWsHi36rKjpX4d0zVnasSsrpJOA=` |
| `lastSeen` encoding of `1767225600000` (2026-01-01T00:00:00Z) | `MTc2NzIyNTYwMDAwMA==` |

Known limits, to document in the migration docs page:
- macOS: a keychain item created by the Electron app is owned by its code signature. The Tauri app gets a one-time "allow access" prompt. If the user denies it, the file fallback still holds the values.
- The MAC address fallback may pick a different interface than Node's `os.networkInterfaces()` on machines without a readable machine id. Rare (only when the native id fails); accepted.

## 5. Rust API

Rust naming conventions (no `get_` prefix). Every public item has rustdoc; `#![deny(missing_docs)]`. The crate root re-exports the public types of `core` (`LicenseManager`, `LicenseState`, `OfflineState`, `LatestAllowedVersion`, `LicenseError`, `LicenseErrorCode`, `MachineFingerprint`), next to the plugin's `Builder` and `LicensemanagerExt` (section 8).

```rust

pub struct LicenseManager { /* Arc<Inner> */ }

impl LicenseManager {
    /// Crate-private: created by the plugin's setup. Runs on the given Tokio handle.

    pub fn on_state_change<F: Fn(LicenseState) + Send + Sync + 'static>(&self, listener: F) -> Subscription;
    pub fn subscribe(&self) -> tokio::sync::watch::Receiver<LicenseState>;

    pub async fn set_license_key(&self, input: &str) -> Result<LicenseState, LicenseError>;
    pub async fn refresh(&self) -> LicenseState;

    pub fn license_key(&self) -> Option<String>;
    pub fn portal_url(&self) -> String;
    pub fn latest_allowed_version(&self) -> LatestAllowedVersion;

    storage_dirs: Option<Vec<PathBuf>>,       // tests
    runtime: tokio::runtime::Handle,          // Tauri's async runtime handle
    testing: Option<TestHooks>,               // fake transport, secret backend, clock (feature "test-util")

    Static(String),
    Fn(Arc<dyn Fn() -> BoxFuture<'static, String> + Send + Sync>),
}
impl From<String> for MachineFingerprint; impl From<&str> for MachineFingerprint;
impl MachineFingerprint { pub fn from_fn<F, Fut>(f: F) -> Self; pub fn from_sync_fn<F>(f: F) -> Self; }

pub enum LicenseState { Loading, MissingKey, Active, InvalidKey, Expired, VersionNotAllowed, MachineLimitReached, OfflineExpired, ClockTampered }

pub enum OfflineState { Online, Offline { valid_until: Option<SystemTime>, remaining: Duration } }

pub enum LicenseErrorCode { NotFound, LicenseExpired, VersionNotAllowed, MachineLimitReached, PlanLimitExceeded, ValidationError, InternalError, NetworkError, InvalidResponse }

pub struct LicenseError { pub code: LicenseErrorCode, pub message: String, pub status: Option<u16>, pub latest_allowed_version: LatestAllowedVersion }
impl LicenseError { pub fn is_locking(&self) -> bool; }

pub enum ConfigError { MissingProductId, MissingPublicKey, InvalidPublicKey(String) }
```

The state strings (`"ACTIVE"`…) and error codes (`"not_found"`…) serialize exactly like the Electron ones.

## 6. Behavior

Port `license-manager.ts` method by method. The summary below is for review; the Electron code is the reference.

### 6.1 Construction
1. Validate options (`ConfigError`), parse the public key once.
2. Build `SecureStore(product_id, storage_dirs)`, `TokenVerifier`, `ClockGuard` (starts its first check and the hourly interval).
3. Read `licenseKey` from the store synchronously.
4. Spawn `init`. `ready()` awaits its result (a shared future; every caller gets the same state).

### 6.2 `init`
- No key: `MISSING_KEY`, no request.
- Key: check the stored token (6.6). If `ACTIVE`, set the token, state `ACTIVE`, resolve `ready`, and revalidate in the background with the background retry policy. Otherwise revalidate with the interactive policy and resolve `ready` with its result.
- After every `await`, return early if the key changed meanwhile (`set_license_key` ran): same guards as Electron (`this.#key !== key`).

### 6.3 `set_license_key(input)`
Trim (keep case). Empty: `validation_error` "The license key is empty", no request. Request with the interactive policy; on success store `licenseKey`, set the key, activate. On failure return the error, store and state untouched.

### 6.4 `refresh()`
Await `ready`; without a key return the state; else revalidate with the interactive policy. Never fails.

### 6.5 Revalidate / activate / lock / offline
- **revalidate(key, policy)**: clear the timer; request; success: activate. Error: map non-`LicenseError` to `network_error`; locking code: lock; anything else: validate offline.
- **activate**: store `licenseToken`, keep the payload, `online = true`, reset retry delay to 5 min, clear latest allowed version, state `ACTIVE`, schedule next.
- **lock(code, latest)**: delete `licenseToken`, drop payload, `online = true`, latest allowed version = `Version`/`NoneAllowed` for `version_not_allowed` only, state from `LOCKED_STATES`. No timer.
- **validate offline**: `online = false`, check the stored token, take its state (`latest_allowed_version = NotApplicable` when it says `VERSION_NOT_ALLOWED`), schedule next, then double the retry delay (cap 1 h).

### 6.6 Stored token check
Await the clock guard's first check. Tampered: `CLOCK_TAMPERED`. No token or verification fails: `OFFLINE_EXPIRED`. Token's `mv` excludes the app version: `VERSION_NOT_ALLOWED` (token kept). Else `ACTIVE` with the payload.

### 6.7 Scheduling
- `ACTIVE` with a payload: `at = compute_refresh_at(payload, min_offline)`; if offline `at = max(at, now + retry_delay)`; then `at = min(at, exp)`.
- `OFFLINE_EXPIRED`, `CLOCK_TAMPERED`, or `VERSION_NOT_ALLOWED` while offline: `at = now + retry_delay`.
- Otherwise no timer. Nothing after `dispose` or without a key.
- Arm in steps of at most 60 minutes, re-reading the **wall clock** (`SystemTime`, through the `Clock` trait) at each step, so sleep or clock changes can't push a validation far past its date. Tokio timers are monotonic and stop during system sleep on macOS: the step re-arm is what catches up.
- `compute_refresh_at`: `min(iat + 2/3 lifetime, max(exp - min_offline, iat + 1 day))`.

### 6.8 Requests
- One in-flight request per `(key, policy)`, shared by callers (`futures::future::Shared`); cleared when it settles. A caller with another policy starts its own request.
- Body: `{ key, fingerprint, version, name, platform }`, JSON, `POST {api}/v1/products/{urlencoded productId}/validate-key`. Timeout per attempt: `min(10 s, remaining budget)`, floor 0.
- Response: non-2xx: parse `{ error: { code, message, latestAllowedVersion } }`; unknown codes become `network_error` (status kept); `latestAllowedVersion` only read for `version_not_allowed` (non-string = `NoneAllowed`). Unparsable body = empty. 2xx without a string `license`: `invalid_response`. Connection error / timeout: `network_error` without status.
- Token failing verification after a 2xx: `invalid_response` with the status.
- Transient = `network_error` without status, or status ≥ 500, 408, 429.

### 6.9 Retry
`with_retry(attempt, is_retryable, policy, cancel)`: deadline = now + budget; on error, wait = `delay/2 + rand*delay/2`; stop (return the error) if not retryable, cancelled, or `now + wait + 1 s > deadline`; sleep (cancellable, returns early on cancel and fails with the last error); delay = `min(delay*2, max)`. Policies: interactive 500 ms / 5 s / 30 s budget, background 2 s / 60 s / 5 min.

### 6.10 Token verification
`jsonwebtoken` with the `rust_crypto` backend (no OpenSSL): `Algorithm::EdDSA` only, `aud = productId`, `sub = key`, `exp` validated, `nbf` validated when present, **leeway 0** (jose's default), required claims `exp`, `iat`, `aud`, `sub`. Then `fp` must equal `fingerprint()`, `iat` and `exp` must be numbers. Payload struct: `iat: i64`, `exp: i64`, `mv: Option<String>` (`null` and missing both mean "every version"), `fp: String`.

### 6.11 Version check
`is_version_allowed(version, mv)`: same regex `^\s*v?(\d+)(?:\.(\d+))?`, same rules (unparsable either side: allowed). Used offline only.

### 6.12 Clock guard
On construction and every 60 min: `HEAD https://google.com`, no cache, 5 s timeout, parse `Date` (`httpdate`). Reachable: tampered = `|now - network| > 5 min`, store `lastSeen = network`. Unreachable or no header: tampered if `now < lastSeen`; store `now` if greater or missing. Never panics or fails; errors swallowed. `ready` resolves after the first check.

### 6.13 Fingerprint
`fingerprint()` cached after first call. Machine raw value:
- macOS: run `ioreg -rd1 -c IOPlatformExpertDevice` (5 s timeout), take the line after `IOPlatformUUID`, strip `=`, whitespace and quotes, lowercase. Running `ioreg`, like Electron, guarantees the same string; no IOKit bindings.
- Windows: registry `HKLM\SOFTWARE\Microsoft\Cryptography\MachineGuid` with `KEY_WOW64_64KEY` (`winreg` crate), whitespace stripped, lowercase.
- Linux and others: `/etc/machine-id`, then `/var/lib/dbus/machine-id`, whitespace stripped, lowercase, first non-empty.
- Any failure: first non-internal, non-zero MAC address (`mac_address` crate), else hostname, lowercased. Never fails.
Option `Static`/`Fn` replaces the raw value (still hashed).

### 6.14 Secure store
`get`: keyring, else first readable non-empty file. `set`: keyring (errors ignored) and every file dir (`create_dir_all`, write, `0o600`). `delete`: keyring (ignored) and every file. Keyring backend loaded once; unavailable (e.g. no Secret Service on headless Linux) means files only. Backend injectable through a `SecretBackend` trait for tests. Calls are blocking (as in Electron); the core runs them on `spawn_blocking` from async paths so a keychain prompt never stalls a runtime worker, except the key read in `new`, which is synchronous like Electron's constructor.

### 6.15 Listeners
State changes only notify when the state differs. Listeners run outside internal locks, each wrapped in `catch_unwind` so a panicking listener can't break the state machine. The `watch` channel is updated before listeners run.

### 6.16 Dispose
Sets disposed, cancels a `CancellationToken` (stops retry sleeps and the scheduler), clears the timer, stops the clock interval. Idempotent. An HTTP request already sent completes but its result is ignored if disposed.

| Constant | Value |
| --- | --- |
| `DEFAULT_API_BASE_URL` | `https://api.licensemanager.dev` |
| `PORTAL_BASE_URL` | `https://app.licensemanager.dev/portal` |

## 8. Tauri plugin layer

### 8.1 Registration

```rust
tauri::Builder::default()
    .plugin(
        tauri_plugin_licensemanager::Builder::new("x7Kp2QaZ", PUBLIC_KEY)
            .min_offline_duration(Duration::from_secs(14 * 86_400))
            // .fingerprint(...).machine_name(...).platform(...).version(...).api_base_url(...)
            .build(),
    )
```

`Builder` exposes every option of the Electron SDK (`storage_dirs` and the test hooks only under the `test-util` feature). Configuration is in code only, not in `tauri.conf.json`: the docs keep telling users to hard-code the public key.

### 8.2 Setup
In `setup`: build the options (version defaults to `app.package_info().version.to_string()`, runtime = Tauri's Tokio handle), create the `LicenseManager`, `app.manage()` it, subscribe to state changes and emit them. On `RunEvent::Exit`: `dispose()`. A `ConfigError` fails the app setup with its message.

### 8.3 Rust access
```rust
pub trait LicensemanagerExt<R: Runtime> { fn license(&self) -> &LicenseManager; }
// implemented for any Manager<R>: app.license().state(), window.license().ready().await …
```
The docs push this for gating: commands that must stay locked check `app.license().state() == LicenseState::Active` in Rust.

### 8.4 Commands and permissions

| Command | Returns | In `default` |
| --- | --- | --- |
| `get_state` | `LicenseState` | yes |
| `ready` | `LicenseState` | yes |
| `get_license` | `Snapshot { state, offline, latestAllowedVersion }` | yes |
| `set_license_key { key }` | `LicenseState`, or error `LicenseErrorDto` | yes |
| `refresh` | `LicenseState` | yes |
| `get_offline_state` | `{ mode: "online" } \| { mode: "offline", validUntil: number \| null, remainingMs: number }` (ms since epoch) | yes |
| `get_latest_allowed_version` | `string \| null`, absent for `NotApplicable` | yes |
| `get_portal_url` | `string` | yes |
| `is_clock_tampered` | `bool` | yes |
| `get_license_key_hint` | last 5 characters of the key, or null | yes |
| `get_license_key` | full key or null | **no** (`licensemanager:allow-get-license-key`) |
| `get_fingerprint` | fingerprint | **no** (`licensemanager:allow-get-fingerprint`) |

`build.rs` generates `allow-*`/`deny-*` for each command; `permissions/default.toml` defines the default set above. Generated files are committed and CI fails when they're stale.

`LicenseErrorDto` (serialized error): `{ code, message, status?, latestAllowedVersion? }`, same shapes as the JS `LicenseError`.

### 8.5 Event
`licensemanager://state-changed`, emitted to all targets with the `Snapshot` payload on every state change.

### 8.6 Mobile
Under `cfg(mobile)`: no keyring/winreg dependencies; the plugin's setup fails with "tauri-plugin-licensemanager supports desktop only (macOS, Windows, Linux)". Revisit after 1.0.

## 9. JS bindings (`@licenseman/tauri`)

## 10. Tests

Target: every Electron test has a Rust (or JS) counterpart with the same name, so parity is reviewable. Coverage ≥ 80% lines on the crate (`cargo llvm-cov --fail-under-lines 80`) and the JS package (vitest thresholds 80/80/80/80 like Electron).

### 10.1 Test infrastructure
- `Transport` trait (`post_validate`, `head_date`): tests use an in-memory fake with a request log and a scripted handler, like Electron's `fetchMock`.
- `Clock` trait: `FakeClock` = `START` + elapsed Tokio time, plus `jump(ms)` for wall clock jumps. Tests run with `#[tokio::test(start_paused = true)]` and `tokio::time::advance`, the equivalent of `vi.useFakeTimers`.
- `SecretBackend` trait: in-memory map backend, or `None` to force the file fallback.
- Ed25519 key pairs generated per test run (`ed25519-dalek` + `pkcs8` for the SPKI PEM, `jsonwebtoken` to sign), plus a second key for "signed by another key".
- All under a `test-util` feature, `#[doc(hidden)]`, not part of the semver API.

### 11.3 Versioning
- Changesets is the single source of truth, with one package (`@licenseman/tauri`), like the Electron repo. Every PR needs a changeset (or `pnpm changeset --empty`), Rust-only changes included.
- `package.json` scripts: `"version": "changeset version && node scripts/sync-versions.mjs"`. The script copies the version to `[package] version` in `Cargo.toml`, then runs `cargo update --workspace` so `Cargo.lock` follows. The "Version Packages" PR thus bumps the npm package and the crate together.
- Semver: a breaking change in the crate or the npm package is a major for both.
- `.changeset/config.json`: same as Electron with `repo: licenseman/licensemanager-tauri`.

### 11.4 Publishing
`pnpm release` = `pnpm build && node scripts/publish.mjs && changeset publish`.
`publish.mjs`: query `https://crates.io/api/v1/crates/tauri-plugin-licensemanager/<version>` (with a User-Agent); run `cargo publish -p tauri-plugin-licensemanager` only if that version is absent. Idempotent, so a failed release can be re-run. Then `changeset publish` publishes npm with provenance, creates the git tag and the GitHub release with the changelog.

Order matters: crate first, npm last. If npm fails after the crate went out, re-running the workflow skips the crate.

### 11.5 Other repo hygiene
- Dependabot for `cargo`, `npm`, `github-actions` (weekly, grouped).
- `deny.toml`: allow MIT/Apache-2.0/BSD/ISC/Unicode/Zlib/MPL-2.0, deny unknown registries and git sources, fail on RustSec advisories.
- `Cargo.toml` metadata: `description`, `license = "MIT"`, `repository`, `homepage = "https://licensemanager.dev/docs/tauri"`, `documentation` (docs.rs), `readme`, `keywords = ["tauri", "tauri-plugin", "license", "licensing", "license-key"]`, `categories = ["authentication", "gui"]`, `include` limited to `src/`, `build.rs`, `permissions/`, README and LICENSE (not `guest-js/`, `examples/` or `node_modules/`).
- docs.rs: `[package.metadata.docs.rs] all-features = true`, `targets` for the three desktop OSes.

## 14. Open questions

1. Names: check `tauri-plugin-licensemanager` (crates.io) and `@licenseman/tauri` (npm) are free before Phase 1.
2. Mobile support after 1.0: keychain (iOS) / Keystore (Android) and a stable device id have no shared Electron behavior to match; needs its own spec.
3. Should the plugin also accept its options from `tauri.conf.json` (`plugins.licensemanager`)? Not in 1.0, to keep the public key in code.
4. The clock check calls `google.com`, like Electron. Any change (e.g. our API's `Date` header) should be made in both SDKs at once.
5. Standalone Rust crate: if Rust apps without Tauri ask for it, move `src/core` to its own crate and re-export it from the plugin (non-breaking).
